2. Project Title & Problem Statement

Formal Project Title
"Create a small-business income/expense tracker with balance summary using Provider."

2.1 Background & Context

Micro, small, and medium enterprises (MSMEs) form the economic backbone of developing economies. Small retail establishments, freelance professionals, repair workshops, and service providers execute dozens of micro-transactions on a daily basis. Despite the critical need for cash flow clarity, a large majority of small-business operators continue to rely on manual paper ledgers (khatabook), unlinked physical receipts, or overly cumbersome enterprise software that requires steep learning curves and recurring subscription fees.

2.2 Core Problem Definition

Manual bookkeeping causes persistent business challenges:

  • Arithmetic Inaccuracies: Frequent calculation errors occur when manually aggregating daily income and running operational expenditures, resulting in distorted balance sheets.
  • Lack of Real-time Cash Visibility: Business owners struggle to immediately evaluate whether their business is operating at a net surplus or cash deficit at any given hour.
  • Absence of Expenditure Categorization: Without structured spending classification (Supplies, Utilities, Transport, Food, Inventory), owners cannot identify operational leakages or optimize operating costs.
  • Overly Complex Existing Solutions: Mainstream accounting tools demand extensive setup, accounting jargon, cloud authentication, backend databases, and heavy processing overhead, intimidating non-technical business proprietors.

2.3 Proposed Solution

The objective of this project is to build an intuitive, zero-dependency, college-viva compliant mobile and web client application developed in Flutter using the Provider pattern. The application delivers real-time net balance evaluation, itemized category breakdown charts, and seamless transaction creation and deletion with strict input validation, providing immediate operational clarity to business owners.

System Architecture & State Model Section 6

6. System Architecture & Reactive State Management

Figure 6.1: High-Level Unidirectional Architecture and Provider Reactive Loop

6.1 Layered Architectural Decomposition

  1. Data Model Layer: Encapsulates pure domain representations. The TransactionModel class models individual ledger records, while the TransactionType enumeration defines immutable debit/credit types.
  2. State Management Layer (Business Logic): Centered around TransactionProvider, which mixes in ChangeNotifier. This layer acts as the single source of truth for all business calculations, maintaining the private transaction list and exposing read-only getters.
  3. Presentation Layer (UI): Divided into top-level screens (HomeScreen, AddTransactionScreen) and reusable atomic widgets (BalanceCard, ExpensePieChart, TransactionCard).

6.2 The Provider Reactive Lifecycle

The application strictly adheres to the unidirectional data flow pattern:

  • State Dispatch: When a user submits a valid transaction, the view invokes context.read<TransactionProvider>().addTransaction(newTx). We use context.read() inside callback handlers to dispatch actions without establishing an unnecessary persistent listener.
  • State Mutation & Notification: The provider mutates its internal _transactions collection and immediately executes notifyListeners().
  • Selective Re-rendering: Flutter's widget tree detects the notification. Widgets wrapped in Consumer<TransactionProvider> or invoking context.watch<TransactionProvider>() execute their build() methods, updating only the affected subtrees.

6.3 Mathematical Calculation Engine

Total Income = Σ (tx.amount | tx.type == TransactionType.income)
Total Expense = Σ (tx.amount | tx.type == TransactionType.expense)
Net Balance = Total Income - Total Expense

9. Source Code: State Management Controller

9.1 Transaction Provider Logic (lib/providers/transaction_provider.dart)

The central state controller managing transaction collections, balance calculations, category grouping, and reactive notifications via notifyListeners(). 

import 'package:flutter/material.dart';
import '../models/transaction.dart';

class TransactionProvider with ChangeNotifier {
  final List<TransactionModel> _transactions = [
    TransactionModel(
      id: DateTime.now().subtract(const Duration(days: 2)).toString(),
      title: 'Product Sales',
      amount: 5000,
      type: TransactionType.income,
      date: DateTime.now().subtract(const Duration(days: 2)),
      category: 'Sales',
    ),
    TransactionModel(
      id: DateTime.now().subtract(const Duration(days: 1)).toString(),
      title: 'Office Supplies',
      amount: 1200,
      type: TransactionType.expense,
      date: DateTime.now().subtract(const Duration(days: 1)),
      category: 'Supplies',
    ),
  ];

  List<TransactionModel> get transactions => [..._transactions].reversed.toList();

  double get totalIncome => _transactions
      .where((tx) => tx.type == TransactionType.income)
      .fold(0.0, (sum, tx) => sum + tx.amount);

  double get totalExpense => _transactions
      .where((tx) => tx.type == TransactionType.expense)
      .fold(0.0, (sum, tx) => sum + tx.amount);

  double get balance => totalIncome - totalExpense;

  Map<String, double> get expensesByCategory {
    Map<String, double> map = {};
    for (var tx in _transactions) {
      if (tx.type == TransactionType.expense) {
        map[tx.category] = (map[tx.category] ?? 0.0) + tx.amount;
      }
    }
    return map;
  }

  void addTransaction(TransactionModel newTx) {
    _transactions.add(newTx);
    notifyListeners(); // Triggers Consumer / context.watch rebuild
  }

  void deleteTransaction(String id) {
    _transactions.removeWhere((tx) => tx.id == id);
    notifyListeners(); // Automatically refreshes UI across all screens
  }
}

9.2 Key Viva Points on State Implementation

  • notifyListeners() acts as an observer pattern dispatcher, notifying registered widgets to run their build methods.
  • _transactions is kept private (prefixed with _) to enforce encapsulation; external widgets access an unmodifiable reversed copy via the getter.

11. Source Code: Form Screen & Input Validation

11.1 Transaction Form Logic (lib/screens/add_transaction_screen.dart)

Features custom segmented controls for income/expense switching, strict numerical validation, a category dropdown, and calendar date selection. 

class _AddTransactionScreenState extends State<AddTransactionScreen> {
  final _formKey = GlobalKey<FormState>();
  final _titleController = TextEditingController();
  final _amountController = TextEditingController();
  TransactionType _selectedType = TransactionType.expense;
  String? _selectedCategory;
  DateTime _selectedDate = DateTime.now();

  void _submitData() {
    if (_formKey.currentState!.validate()) {
      final amount = double.tryParse(_amountController.text) ?? 0.0;
      if (_selectedCategory == null) {
        ScaffoldMessenger.of(context).showSnackBar(
          const SnackBar(content: Text('Please select a category')),
        );
        return;
      }
      final newTx = TransactionModel(
        id: DateTime.now().toString(),
        title: _titleController.text.trim(),
        amount: amount,
        type: _selectedType,
        date: _selectedDate,
        category: _selectedCategory!,
      );

      // context.read dispatches mutation without ongoing subscription
      context.read<TransactionProvider>().addTransaction(newTx);
      Navigator.pop(context);
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('New Transaction')),
      body: Form(
        key: _formKey,
        child: ListView(
          padding: const EdgeInsets.all(24),
          children: [
            // Segmented Button & Amount field
            TextFormField(
              controller: _amountController,
              decoration: const InputDecoration(labelText: 'Amount (₹)'),
              keyboardType: const TextInputType.numberWithOptions(decimal: true),
              validator: (val) => (val == null || (double.tryParse(val) ?? 0) <= 0) ? 'Enter amount > 0' : null,
            ),
            TextFormField(
              controller: _titleController,
              decoration: const InputDecoration(labelText: 'Title'),
              validator: (val) => (val == null || val.trim().isEmpty) ? 'Enter title' : null,
            ),
            FilledButton(onPressed: _submitData, child: const Text('Save Transaction')),
          ],
        ),
      ),
    );
  }
}

15.2 Frequently Asked Viva-Voce Questions

Q1: What is the Provider package and why is it used instead of setState()?
Answer: setState() only triggers local widget rebuilds and requires drilling state down through constructor arguments. Provider leverages Flutter's InheritedWidget to make data globally accessible and selectively rebuilds only the widgets that depend on updated fields.

Q2: What is the exact difference between context.read() and context.watch()?
Answer: context.watch<T>() subscribes to changes and re-runs the widget's build() method whenever notifyListeners() is called. context.read<T>() accesses the provider without subscribing, making it ideal for event handlers like button presses.

Q3: What role does ChangeNotifier play?
Answer: ChangeNotifier is a class in the Flutter Foundation SDK that provides change notifications using the Observer pattern. When business state changes, calling notifyListeners() notifies all listening widgets to rebuild.
